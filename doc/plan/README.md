# 未來專案規劃 (Plan)

在此紀錄追蹤系統之發展輪廓與里程碑。

## 行程目標與改善亮點

### 階段一：效能與通知穩定性 (進行中)
*   [ ] 建立醫院 API 回應時間的緩存控制，降低同一時間觸發多支通知爬蟲時互相牽扯的問題。
*   [ ] 重構 Notification 機制中的多封信與多則 LINE 訊息批次 (Batch) 處理降低外部依賴調用次數。

### 階段二：支援更多跨地域醫院整合
*   [ ] 增設北中南更多地區性的醫學中心資料來源。
*   [ ] 解析模組 (`scrapers/`) 將定義更標準化的 Base 介面。

### 階段三：高階分析與可視化
*   [ ] 實作更多進階使用者的追蹤條件（如：等待時間超過 N 小時才通知）。
*   [ ] 前端 Dashboards 升級，以提供各時段的詳細歷史塞車趨勢圖預測。
